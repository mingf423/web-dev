## 1. 为什么前端要"异步"？—— JS 是单线程的

### 1.1 先回想 Java 是怎么做的

```java
// Java：同步阻塞。这行代码会"卡住"当前线程，直到接口返回
String result = restTemplate.getForObject(url, String.class);
// ↑ 如果后端要 3 秒才返回，这个线程就干等 3 秒，啥也不干
System.out.println("拿到结果了：" + result);
```

> Java 的底气是**多线程**：一个线程卡住了，别的线程继续跑。你开几百个线程都没压力。

### 1.2 JS 的情况完全不同

```js
// JS：单线程。主线程只有一条，如果这里阻塞 3 秒，整个页面就"冻住"3 秒
// 用户点按钮、滚动页面、输入文字 —— 全部没反应，浏览器甚至提示"页面无响应"
```

> JS 的解决思路：**我不等你了，你先去忙，结果好了通知我**。

```js
// fetch 立即返回，不阻塞。页面继续响应，数据到了再执行回调
fetch(url).then(res => res.json()).then(data => {
    console.log('数据到了', data);   // ← 这段"以后"才执行
});
console.log('这行先执行');           // ← 这行"立刻"执行
```

### 1.3 核心认知：执行顺序变了

```js
console.log('1. 开始');

fetch(url).then(() => {
    console.log('3. 数据返回了（异步回调，后执行）');
});

console.log('2. 结束');
// 实际输出顺序：1 → 2 → 3
// 不是 1 → 2 → 3 吗？不是，是 1 → 2（立刻）→ 3（数据回来后）
```

> **一句话总结**：JS 里凡是涉及"等一会儿"的操作（网络请求、定时器、读文件），
> 都是**异步**的 —— 代码不会卡在那里等，而是先往下执行，等结果好了再回来执行回调。

### 🎯 这一节回答了

> 为什么 Java 里 `httpClient.get()` 是"等结果"，而 JS 里 `fetch()` 是"先走，结果回来再叫你"？

### ✅ 检查点

- [ ] 知道 JS 是单线程，不能像 Java 那样阻塞等待
- [ ] 知道异步代码的执行顺序：同步的先执行，回调的"以后"执行

## 2. Promise —— 异步操作的结果容器

> **Promise ≈ `CompletableFuture<T>`。** 这是今天最核心的概念，理解它，`then`/`catch`/`await` 全都顺了。

### 2.1 一句话理解

```
Promise 是一个"未来才有结果"的容器。
创建时结果是"未定"的（pending），
等异步操作完成，结果变成"成功"（fulfilled）或"失败"（rejected），
而且一旦确定，永远不变。
```

### 2.2 Java 类比（一模一样）

```java
// Java：CompletableFuture
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    return restTemplate.getForObject(url, String.class);   // 异步执行
});
// future 现在还没结果，但你能拿着它"预约"后续处理
future.thenApply(result -> "结果：" + result);
```

```js
// JavaScript：Promise
const promise = fetch(url);   // 立即返回一个 Promise，还没结果
promise.then(res => res.json());   // "预约"成功后的处理
```

| | Promise | CompletableFuture |
|---|---------|-------------------|
| 结果容器 | ✅ | ✅ |
| 三种状态 | pending/fulfilled/rejected | 未完成/正常完成/异常完成 |
| 成功回调 | `.then(fn)` | `.thenApply(fn)` |
| 失败回调 | `.catch(fn)` | `.exceptionally(fn)` |
| 链式调用 | `.then().then().catch()` | `.thenApply().thenApply().exceptionally()` |

### 2.3 Promise 的三种状态

```js
// 创建一个 Promise（通常你不用自己 new，fetch 已经返回了 Promise）
const p = new Promise((resolve, reject) => {
    // 异步操作成功后调用 resolve(结果)
    // 失败后调用 reject(错误)
    setTimeout(() => resolve('成功啦'), 1000);
});
// p 现在的状态：pending（进行中）
// 1 秒后：fulfilled（成功），值是 '成功啦'
```

```js
// 失败的 Promise
const p2 = new Promise((resolve, reject) => {
    setTimeout(() => reject('出错了'), 1000);
});
// 1 秒后：rejected（失败），错误是 '出错了'
```

> ⚠️ **重要**：`resolve` 和 `reject` 只能调用一次，Promise 状态一旦确定就**不会变**。
> 就像 `CompletableFuture` 完成之后，再 `complete()` 也没用。

### 🎯 这一节回答了

> 为什么 `fetch(url)` 返回的东西能 `.then()`？因为它返回的是个 Promise。

### ✅ 检查点

- [ ] 知道 Promise 有 pending/fulfilled/rejected 三种状态
- [ ] 知道 Promise ≈ CompletableFuture
- [ ] 知道状态一旦确定就不变

## 3. `.then()` / `.catch()` —— 成功/失败回调

### 3.1 基本用法

```js
fetch(url)
    .then(res => {                    // 成功：处理结果
        console.log('成功了', res);
    })
    .catch(err => {                   // 失败：处理错误
        console.log('失败了', err);
    });
```

```java
// Java 等价
future
    .thenApply(res -> { ... })
    .exceptionally(err -> { ... });
```

### 3.2 链式调用（每个 then 返回新 Promise）

```js
fetch(url)                          // 返回 Promise<Response>
    .then(res => res.json())        // 返回 Promise<数据>，把 Response 转成 JSON
    .then(data => {                 // 拿到上一步的返回结果
        console.log(data);
    })
    .catch(err => {                 // 上面任何一步出错，都会跳到这里
        console.error(err);
    });
```

> 这就是项目里 `.then().then().catch()` 链式写法的原理：每个 `.then()` 都返回一个新 Promise，
> 所以能一直 `.then()` 下去，最后用 `.catch()` 兜底。

### 3.3 ⚠️ 最容易混淆：catch 的位置

```js
// 错误写法：catch 在中间，后面的 then 还会执行
fetch(url)
    .then(res => res.json())
    .catch(err => console.log('出错了'))   // 只兜住前面的错误
    .then(data => console.log(data));      // 无论前面是否出错，这里都会执行

// 正确写法：catch 放最后，兜住整条链
fetch(url)
    .then(res => res.json())
    .then(data => console.log(data))
    .catch(err => console.log('出错了'));  // 兜住整条链
```

### 🎯 这一节回答了

> 为什么能 `.then().then().catch()` 一直链下去？每个 `.then()` 返回的到底是什么？

### ✅ 检查点

- [ ] `.then()` = 成功回调，`.catch()` = 失败回调
- [ ] 每个 `.then()` 返回新 Promise，所以能链式调用
- [ ] `catch` 放在最后，兜住整条链

## 4. fetch —— 浏览器原生的 HTTP 请求

> `fetch` 是浏览器自带的发请求函数，相当于 Java 的 `RestTemplate`。你不需要装任何库。

### 4.1 最基础的 GET 请求

```js
fetch('https://jsonplaceholder.typicode.com/users')
    .then(res => res.json())      // ① 拿到 Response，转成 JSON
    .then(data => {               // ② 拿到真正的数据
        console.log(data);
    })
    .catch(err => {               // ③ 出错兜底
        console.error('请求失败', err);
    });
```

> ⚠️ **关键：fetch 要"两步"**。`fetch()` 拿到的是 `Response` 对象（含状态码、响应头），
> 不是你要的数据。必须再调一次 `.json()` 才能拿到 JSON 数据。
> 类比 Java：`fetch()` ≈ 拿到 `HttpResponse`，`.json()` ≈ 解析 body 字符串。

### 4.2 完整的项目式写法（带状态判断）

```js
fetch(url)
    .then(res => {
        if (!res.ok) {                       // res.ok = 状态码 200-299
            throw new Error('HTTP ' + res.status);
        }
        return res.json();
    })
    .then(data => {
        // 这里处理 data（项目里会再判断 data.code）
        if (data.code === 0) {
            console.log(data.data);
        }
    })
    .catch(err => {
        console.error(err);
    });
```

### 4.3 你们项目里其实不用 fetch，而是封装的 axios

```js
// 项目里不会直接写 fetch，而是封装后的 axios 方法（Day11 会讲）
import { getAction, postAction, httpAction } from '@/api/manage';

getAction('/api/user/list', { pageNo: 1, pageSize: 10 })
    .then(res => {
        if (res.code === 0) {
            this.dataSource = res.data.records;
        }
    });
```

> **本质一样**：`getAction` 内部就是用 axios（axios 内部又是基于 Promise）发请求，
> 所以它返回的也是 Promise，你照样能 `.then()` / `.catch()` / `await`。

### 🎯 这一节回答了

> 前端到底怎么和后端通信？`fetch` 和项目里的 `getAction` 是什么关系？

### ✅ 检查点

- [ ] `fetch(url)` 返回 Promise，要 `.json()` 才拿到数据
- [ ] 知道项目里的 `getAction`/`postAction` 就是封装过的请求方法
- [ ] 知道统一响应格式 `{ code, type, message, data }`，`code === 0` 才算成功

## 5. async/await —— 同步的写法写异步

> `.then()` 链一旦长了就变成"回调地狱"。`async/await` 让你**用同步的写法写异步代码**，
> 这是你最舒服的部分 —— 因为它看起来和 Java 的同步代码几乎一样。

### 5.1 对比：then 链 vs async/await

```js
// ① 用 then 链（嵌套深了很痛苦）
function loadUsers() {
    fetch(url)
        .then(res => res.json())
        .then(data => {
            console.log(data);
        })
        .catch(err => {
            console.error(err);
        });
}

// ② 用 async/await（看起来就是同步代码）
async function loadUsers() {
    try {
        const res = await fetch(url);     // await = "等这个 Promise 出结果"
        const data = await res.json();    // 再等 json() 出结果
        console.log(data);
    } catch (err) {                       // 用你最熟悉的 try/catch 抓错！
        console.error(err);
    }
}
```

### 5.2 规则（就两条）

```js
// 规则1：函数前面加 async，函数就返回 Promise
async function getData() {
    return '结果';
}
// 调用时：getData() 返回 Promise，可以 .then() 或 await

// 规则2：await 只能在 async 函数里用
async function main() {
    const result = await getData();   // await 等 Promise 出结果
    console.log(result);              // '结果'
}
```

### 5.3 Java 类比

```java
// Java：你希望异步代码能这样写（但 CompletableFuture.get() 会阻塞）
String result = future.get();   // 阻塞等待，拿到结果

// JS：await 就是"不阻塞线程的 get()"
const result = await future;    // 不阻塞，拿到结果，但代码看起来是同步的
```

> **一句话**：`await` = `CompletableFuture.get()` 的效果（拿到结果），
> 但没有阻塞线程的副作用。这是 JS 单线程模型下的"魔法"。

### 5.4 项目里的真实写法

```js
// 项目里 loadData 方法通常长这样（Day06/Day11 会重点讲）
async loadData() {
    try {
        const res = await getAction(this.url.list, this.queryParam);
        if (res.code === 0) {
            this.dataSource = res.data.records;
            this.ipagination.total = res.data.total;
        } else {
            this.$message.error(res.message);
        }
    } catch (err) {
        this.$message.error('请求失败，请稍后重试');
    }
}
```

> 这个 `async loadData()` + `try/catch` + `await getAction()` 的组合，是**全项目出现频率最高的代码模式**。

### 🎯 这一节回答了

> `async function` 和 `await` 是干嘛的？为什么异步代码能写得像同步代码？

### ✅ 检查点

- [ ] `async` 标记的函数返回 Promise
- [ ] `await` 只能在 async 函数里用，作用是"等结果"
- [ ] `try/catch` 能捕获 await 的异常
- [ ] 能看懂 `async loadData() { const res = await getAction(url); ... }`

```js
// ① 查询数据（then 链式写法）

    if (res.code === 0) {
        this.$message.success('保存成功');
        this.loadData();
    }
}

// ④ 错误处理
getAction(url).then(res => { ... }).catch(err => {
    this.$message.error('请求失败');
});
```

## 8. 速查表

### 异步相关概念

| 概念 | 作用 | Java 类比 |
|------|------|-----------|
| `Promise` | 异步结果容器 | `CompletableFuture<T>` |
| `.then(fn)` | 成功回调 | `.thenApply()` |
| `.catch(fn)` | 失败回调 | `.exceptionally()` |
| `.finally(fn)` | 无论成败都执行 | `whenComplete()` |
| `async` | 标记函数返回 Promise | 无直接对应 |
| `await` | 等结果（不阻塞） | `.get()` 但非阻塞 |

### HTTP 请求方法

| 方式 | 代码 | 说明 |
|------|------|------|
| 原生 | `fetch(url)` | 浏览器自带，两步拿数据 |
| 项目封装 | `getAction(url, params)` | GET 请求 |
| 项目封装 | `postAction(url, params)` | POST 请求 |
| 项目封装 | `httpAction(url, data, method)` | 通用请求 |

### 统一响应格式（务必记住）

```js
{
    code: 0,          // 0 = 成功，非 0 = 失败
    type: 'success',  // success / info / warning / error
    message: '操作成功', // 失败时的原因
    data: {}          // 成功时的数据
}
// 判断成功永远用：if (res.code === 0) { ... }
```
