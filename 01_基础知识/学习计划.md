### Day06 — Vue 组件：看懂 `<script>` 里的东西

> **为什么学**：模板看懂了，但 `data()`、`methods`、`computed`、`watch`、`props`、`$emit` 这些才是逻辑核心。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| `data()` | 组件的本地状态 | 类的成员变量 | ⭐⭐⭐ |
| `methods` | 组件的方法 | 类的方法 | ⭐⭐⭐ |
| `computed` | 计算属性（有缓存） | getter 方法 + 缓存 | ⭐⭐⭐ |
| `watch` | 监听数据变化 | `PropertyChangeListener` | ⭐⭐ |
| `props` | 父传子的参数 | 构造器参数 | ⭐⭐⭐ |
| `$emit` | 子传父的事件 | 回调函数 | ⭐⭐⭐ |
| 生命周期 | `created` / `mounted` | `@PostConstruct` / `init()` | ⭐⭐⭐ |

```js
// 项目中的组件结构（看懂就是胜利）
export default {
    name: "UserList",                    // 组件名
    mixins: [JeecgListMixin],            // 混入（≈ 继承工具类）
    components: { CommonTable },         // 注册子组件
    props: { userId: String },           // 父组件传过来的参数
    data() {                             // 本地状态（≈ 成员变量）
        return { columns: [], loading: false };
    },
    computed: {                          // 计算属性（有缓存）
        displayName() { return this.user.name || '未知'; }
    },
    watch: {                             // 监听器
        userId(newVal) { this.loadData(); }
    },
    created() { this.loadData(); },       // 生命周期：组件创建后执行
    methods: {                           // 方法
        async loadData() { ... },
        handleEdit(row) { ... }
    }
}
```

**实践**：写一个父组件 + 子组件，父组件传 `title` 给子组件，子组件通过按钮把用户操作 `$emit` 回父组件。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| data/methods | `data() { return { queryParam: {...} } }` |
| computed | `computed: { hasSelected() { return this.selection.length > 0 } }` |
| props | `props: { visible: Boolean, editData: Object }` |
| $emit | `this.$emit('update:visible', false)` |
| created/mounted | `created() { this.loadData(); }` |

### Day09 — Vue Router：看懂路由和页面跳转

> **为什么学**：点左侧菜单能跳到不同页面，靠的就是 Vue Router。你要能看懂路由配置、知道 URL 和页面的对应关系。

| 知识点 | 学会什么 | 优先级 |
|--------|----------|--------|
| 路由配置 | `path` + `component` = URL ↔ 页面映射 | ⭐⭐⭐ |
| 嵌套路由 | `children` 数组 = 菜单层级 | ⭐⭐⭐ |
| 路由元信息 | `meta: { menuShow, menuName, menuIcon }` | ⭐⭐ |
| 动态路由 | `/user/:id` → `this.$route.params.id` | ⭐⭐ |
| 编程式导航 | `this.$router.push('/page')` | ⭐⭐ |

```js
// 项目中的路由配置（看懂就行）
{
    path: '/bill',
    name: 'Bill',
    component: Home,
    meta: { menuShow: true, menuName: '账单管理', menuIcon: 'el-icon-document' },
    children: [
        {
            path: '/bill/medinsBill',
            name: 'MedinsBill',
            component: () => import('@/views/bill/medinsBill.vue'),  // 懒加载
            meta: { menuShow: true, menuName: '机构账单' }
        }
    ]
}
// 访问 /bill/medinsBill → 加载 @/views/bill/medinsBill.vue
```

**实践**：打开项目 `src/router/` 目录，画出项目的页面结构树。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| 路由跳转 | `this.$router.push({ path: '/bill/detail', query: { id: row.id } })` |
| 获取参数 | `const id = this.$route.query.id` |

### Day10 — Vuex：看懂全局状态管理

> **为什么学**：有些数据（用户信息、字典数据、权限）要在多个页面共享，Vuex 就是前端的"全局变量管理器"。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| `state` | 全局数据 | 静态成员变量 | ⭐⭐⭐ |
| `getters` | 从 state 计算出的值 | getter 方法 | ⭐⭐ |
| `mutations` | 同步修改 state | `synchronized setXxx()` | ⭐⭐⭐ |
| `actions` | 异步操作后 commit mutation | Service 方法 | ⭐⭐⭐ |
| `this.$store.state.xxx` | 在组件中读取 | `GlobalData.getXxx()` | ⭐⭐⭐ |
| `this.$store.dispatch('xxx')` | 在组件中触发 action | `service.doSomething()` | ⭐⭐ |

```js
// 项目中的 Vuex 用法（看懂就行）
// 读取
this.userInfo = this.$store.state.userInfo;
// 调用
this.$store.dispatch('getDictList', 'status_type').then(res => { ... });
```

**实践**：打开项目 `src/store/` 目录，理解 store 的结构。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| 读取 state | `this.$store.state.userInfo` |
| 调用 action | `this.$store.dispatch('GetUserInfo')` |

### Day11 — CommonTable：啃透项目核心组件

> **为什么学**：你们项目强制要求所有表格用 `CommonTable`，这是全项目出现频率最高的组件。啃透它，大半页面你都能看懂。

```vue
<!-- 项目页面中反复出现的模式 -->
<template>
    <common-table
        ref="refTable"
        :dataSource="dataSource"
        :columns="columns"
        :pagination="ipagination"
        :loading="loading"
        @handleCurrentChange="handleTableChange"
        @handleSizeChange="handleSizeChange"
    >
        <el-table-column slot="table_oper" label="操作" fixed="right">
            <template slot-scope="scope">
                <el-link type="primary" @click="handleEdit(scope.row)">编辑</el-link>
            </template>
        </el-table-column>
    </common-table>
</template>
```

**逐行解释**：

| 代码 | 含义 |
|------|------|
| `:dataSource="dataSource"` | 把 JS 中的 `dataSource` 数组传给表格 |
| `:columns="columns"` | 列定义数组 `[{prop:'name', label:'姓名'}]` |
| `:pagination="ipagination"` | 分页信息 `{current:1, total:0, pageSize:10}` |
| `:loading="loading"` | 加载中状态 |
| `@handleCurrentChange="..."` | 翻页时触发的方法 |
| `slot="table_oper"` | 在表格中插入自定义"操作列" |
| `slot-scope="scope"` | `scope.row` 拿到当前行的数据 |

**实践**：找到 CommonTable 源码（`src/components/views/table/CommonTable.vue`），对照你的 Java 项目中的 BaseController/BaseService，理解"公共组件提效"的思路。

### Day12 — JeecgListMixin + CRUD 流程：看懂增删改查

> **为什么学**：项目中的列表页都混入了 `JeecgListMixin`，它提供了 `loadData()`、`searchQuery()`、`searchReset()` 等方法，不懂它就不知道为什么这些方法突然能用了。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| Mixin | 混入，多组件共享逻辑 | 抽象父类 / 接口默认方法 | ⭐⭐⭐ |
| `JeecgListMixin` | 提供了列表页的标准流程 | `BaseController` | ⭐⭐⭐ |
| CRUD 流程 | 查 → 增 → 改 → 删 | Controller → Service → DAO | ⭐⭐⭐ |

```js
// 一个标准 CRUD 操作的数据流
// 查询
searchQuery() → loadData() → getAction(url.list, queryParam) → res.data.records → dataSource

// 新增
handleAdd() → dialogVisible = true → 填表单 → handleSave()
    → httpAction(url.add, formData, 'post') → this.$message.success('新增成功') → loadData()

// 编辑
handleEdit(row) → editData = {...row} → dialogVisible = true → 修改表单
    → handleSave() → httpAction(url.edit, formData, 'put') → loadData()

// 删除
handleDelete(row) → this.$confirm('确认删除？') → httpAction(url.delete, {id: row.id}, 'delete') → loadData()
```

**实践**：打开项目中一个列表页 `.vue` 文件，按上述流程在代码中标注每一步对应的位置。

**走读清单**（打开任意一个 `.vue` 文件，按顺序标注）：

```
□ <template> 区
```

### Day14 — Bug 调试实战：前端问题排查套路

> **为什么学**：你的目标是"能改前端 bug"。学完前面的知识后，Day14 专门练怎么排查问题。

**常见 Bug 类型及排查思路**：

| 症状 | 最可能的原因 | 排查工具 |
|------|-------------|----------|
| 点了没反应 | 事件没绑定 / 方法未定义 | F12 → Console 看报错 |
| 数据不显示 | 接口没返回 / 数据没赋值到 dataSource | F12 → Network 看接口 |
| 样式错乱 | CSS 被覆盖 / scoped 没加 | F12 → Elements 看样式 |
| `undefined` / `null` | 对象解构层级不对 | `console.log` / debugger |
| 路由跳不过去 | path 写错 / 权限 meta 限制 | F12 → Console |
| 接口 401/403 | Token 过期 / 权限不足 | F12 → Network → Headers |

**前端调试三板斧**：

```
1. F12 → Console   看报错信息（等于看 Java 的异常堆栈）
2. F12 → Network   看接口请求/响应（等于看 HTTP 请求日志）
3. F12 → Sources   打断点调试（等于 IDEA 的 Debug 模式）
```

**实践**：在 Day01 的 `hello.html` 中故意制造一个 bug（比如把 id 写错），练习用 F12 定位修复。
