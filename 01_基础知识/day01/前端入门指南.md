## 1. HTML 结构 —— 前端的"类定义"

```html
<!DOCTYPE html>
<html lang="zh">
<head>
    <meta charset="UTF-8">
    <title>Java 开发者的前端第一步</title>
</head>
<body>
    <!-- 页面可见内容写在这里 -->
</body>
</html>
```

### Java 类比

| 前端概念 | Java 类比 | 说明 |
|----------|-----------|------|
| `<html>` | `class` 关键字 | 整个页面的根容器 |
| `<head>` | 类的 `import` 区 + 注解 | 元信息、样式、脚本声明，不直接渲染 |
| `<body>` | 类的 `main` 方法体 | 用户**能看到**的所有内容 |
| `<!DOCTYPE html>` | 编译器版本声明 | 告诉浏览器"按 HTML5 标准解析" |
| `<meta charset="UTF-8">` | `Charset.forName("UTF-8")` | 字符编码，避免中文乱码 |

### 🎯 关键认知

> HTML **不是编程语言**，它是**标记语言**。想象你在用 XML 定义 UI 布局 —— 用标签声明"这里有个按钮、这里有个标题"，不用写逻辑。

## 2. CSS —— 前端的"样式属性"

```html
<style>
    body {
        font-family: system-ui;
        max-width: 500px;
        margin: 100px auto;
        text-align: center;
    }
</style>
```

### 语法拆解

```
选择器 {
    属性: 值;
    属性: 值;
}
```

### Java 类比

| CSS 概念 | Java 类比 | 说明 |
|----------|-----------|------|
| `body` | 对象引用 | 选中页面上所有 `<body>` 元素 |
| `{ }` | `{ }` | 一样，都是代码块 |
| `font-family: system-ui` | `setFont(...)` | 设置字体 |
| `max-width: 500px` | `setMaxWidth(500)` | 最大宽度 500 像素 |
| `margin: 100px auto` | 上下边距 100px，左右自动（=居中） |
| `text-align: center` | 文字水平居中 |

### 🎯 关键认知

> 前端三大件的分工：
> - **HTML** = 有什么（内容/结构）
> - **CSS** = 长什么样（样式/布局）
> - **JavaScript** = 怎么动（交互/逻辑）

像 Java Swing 里：HTML ≈ 你在 `JFrame` 上放了什么组件，CSS ≈ `setSize()`/`setBackground()`，JS ≈ `addActionListener()`。

## 3. JavaScript 基础 —— 你已会的（大部分）

### 3.1 变量声明

```js
const greetBtn = document.getElementById('greetBtn');   // 不可重新赋值
const greeting = document.getElementById('greeting');   // 不可重新赋值
const nameInput = document.getElementById('nameInput');  // 不可重新赋值
```

| JS | Java | 说明 |
|----|------|------|
| `const` | `final` | 不可重新赋值（但对象内部属性可变） |
| `let` | 普通变量 | 可以重新赋值 |
| `var` | ~~不要用~~ | 老语法，有作用域陷阱 |

```js
// Java 对比
// Java:        final String name = "张三";
// JavaScript:  const name = "张三";
//
// Java:        String name = "张三";
// JavaScript:  let name = "张三";
```

### 3.2 函数 / 方法

```js
greetBtn.addEventListener('click', function() {
    // 这是匿名函数（≈ Java 的 Lambda）
    const name = nameInput.value;
    if (name.trim()) {
        greeting.textContent = `你好，${name}！`;
    }
});
```

Java 对比：

```java
// JavaScript 匿名函数
button.addEventListener("click", () -> {
    String name = input.getValue();
    if (!name.isBlank()) {
        label.setText("你好，" + name + "！");
    }
});

// 相当于 Java 的：
greetBtn.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        String name = nameInput.getValue();
        // ...
    }
});
```

### 3.3 模板字符串 —— 前端的字符串格式化

```js
`你好，${name}！`          // JavaScript：反引号 + ${}
```

```java
String.format("你好，%s！", name)   // Java：String.format + %s
```

### 🎯 关键认知

> JavaScript 是**弱类型**、**动态**语言。没有 `int`/`String` 类型声明，一个 `let` 走天下。刚开始会觉得"不安全"，习惯了会很灵活。

## 4. DOM 操作 —— 前端的"操控页面 API"

DOM = **Document Object Model**，浏览器把 HTML 解析成一颗**对象树**，你操作这棵树 = 操作页面。

### 4.1 查找元素（≈ Java 的 findById）

```js
document.getElementById('greetBtn')        // 按 id 查找，返回单个元素
document.querySelector('.my-class')        // 按 CSS 选择器查找，返回第一个
document.querySelectorAll('div')           // 查找所有，返回 NodeList（≈ List）
```

Java 对比：

```java
// Java MyBatis:   mapper.findById(1L)
// JavaScript DOM:  document.getElementById('greetBtn')
```

### 4.2 读取/修改内容

```js
// 读取输入框的值（input 用 .value）
const name = nameInput.value;

// 修改元素的文本
greeting.textContent = '请输入名字后再点我！';

// 更常用的：修改 HTML 内容
element.innerHTML = '<strong>加粗文字</strong>';
```

### 4.3 事件监听（≈ addListener）

```js
// JavaScript
element.addEventListener('事件名', 回调函数);
element.addEventListener('click', function() { ... });        // 点击
element.addEventListener('input', function() { ... });        // 输入
element.addEventListener('change', function() { ... });       // 值变化
element.addEventListener('submit', function(e) {
    e.preventDefault();  // 阻止默认行为（阻止表单提交）
});
```

Java 类比：

| JS 事件 | Java Swing 事件 |
|---------|-----------------|
| `click` | `ActionListener.actionPerformed()` |
| `input` | `DocumentListener.insertUpdate()` |
| `change` | `ItemListener.itemStateChanged()` |
| `keydown` | `KeyListener.keyPressed()` |

## 5. Bug 复盘 —— 你刚才遇到的 `Cannot read properties of null`

```js
const nameInput = document.getElementById('nameInput');  // → null！
const name = nameInput.value;  // 💥 空指针，等价于 Java 的 NullPointerException
```

### Java 对比

```java
// Java
User user = userDao.findById(999L);  // 返回 null
String name = user.getName();        // 💥 NullPointerException

// 防御式编程
if (user != null) {
    String name = user.getName();
}
```

```js
// JavaScript 防御式
const nameInput = document.getElementById('nameInput');
if (nameInput) {
    console.log(nameInput.value);
}
```

### 🎯 根因

JS 在 HTML **之前**就执行了，或者 DOM 中根本**没有**这个 id 的元素。两种常见情况：

| 原因 | 解决方案 |
|------|----------|
| 元素不存在 | 先写 HTML 元素，再写 JS |
| JS 执行早于 HTML 渲染 | 把 `<script>` 放在 `</body>` 前面，或用 `DOMContentLoaded` 事件 |

## 6. 数据流全景图

```
用户输入 "张三"
    │
    ▼
┌──────────────────────────────────────────┐
│  <input id="nameInput" />                 │   ← HTML 定义结构
│  nameInput.value  →  "张三"              │   ← JS 读取值
└──────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────┐
│  greetBtn.addEventListener('click', () => {│
│      greeting.textContent = `你好，张三！` │   ← JS 修改 DOM
│  })                                       │
└──────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────┐
│  <h1 id="greeting">你好，张三！</h1>      │   ← 页面自动重绘
└──────────────────────────────────────────┘
```

### 与 Java 后端对比

| 步骤 | Java 后端 | 前端 JS |
|------|-----------|---------|
| 接收输入 | `request.getParameter("name")` | `element.value` |
| 处理逻辑 | Service 层 | 事件回调函数 |
| 返回结果 | `response.getWriter().write(json)` | `element.textContent = ...` |

> 前端本质就是：**读 DOM → 处理 → 写 DOM**，只是没有了"请求-响应"的边界，所有操作都是在用户浏览器里完成的。

### Day03 — JavaScript 深入：看懂项目中的数据处理

> **为什么学**：项目中到处都是 `.map()`、`.filter()`、`...` 展开、`{}` 解构，看不懂这些就读不懂逻辑。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| 数组 `.map()` | 转换数组每个元素 | `stream().map()` | ⭐⭐⭐ |
| 数组 `.filter()` | 过滤数组 | `stream().filter()` | ⭐⭐⭐ |
| 数组 `.find()` | 查找单个元素 | `stream().findFirst()` | ⭐⭐ |
| 对象 `{}` | JS 的"万能容器" | `Map<String, Object>` | ⭐⭐⭐ |
| 解构 `const { a, b } = obj` | 从对象中提取字段 | ⭐⭐⭐ |
| 展开 `...` | 合并数组/对象 | ⭐⭐⭐ |
| 可选链 `?.` | 安全访问深层属性 | ⭐⭐ |

```js
// 这行代码你看得懂吗？（项目中大量出现）
const ids = list.filter(i => i.status === 1).map(i => i.id);

// Java 等价写法：
// List<Long> ids = list.stream()
//     .filter(i -> i.getStatus() == 1)
//     .map(i -> i.getId())
//     .collect(Collectors.toList());
```

**实践**：给一个用户数组，完成：筛选活跃用户 → 提取姓名 → 按年龄排序。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| 解构赋值 | `const { code, data, message } = res` |
| 数组方法链 | `dataSource.filter(i => i.checked).map(i => i.id)` |
| 展开合并 | `this.queryParam = { ...this.queryParam, pageNo: 1 }` |

### Day04 — 异步请求：看懂前后端怎么通信

> **为什么学**：项目中每个页面的数据都来自后端 API，`getAction(url, params).then(res => {...})` 这种代码遍布全项目。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| Promise | 异步操作的结果容器 | `CompletableFuture<T>` | ⭐⭐⭐ |
| `.then()` | 成功后的回调 | `.thenApply()` | ⭐⭐⭐ |
| `.catch()` | 失败后的回调 | `.exceptionally()` | ⭐⭐ |
| `async/await` | 同步写法写异步 | `CompletableFuture` + 虚线程 | ⭐⭐⭐ |
| axios / fetch | 发 HTTP 请求 | `RestTemplate` / `HttpClient` | ⭐⭐⭐ |

```js
// 项目中真实写法（看懂就行）
getAction('/api/user/list', { pageNo: 1, pageSize: 10 })
    .then(res => {
        if (res.code === 0) {
            this.dataSource = res.data.records;
            this.ipagination.total = res.data.total;
        }
    });
```

**实践**：调用免费 API `https://jsonplaceholder.typicode.com/users`，获取用户列表并 `console.log` 输出。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| Promise 链 | `getAction(url, params).then(res => {...}).catch(err => {...})` |
| async/await | `async loadData() { const res = await getAction(url, params); }` |
| 响应解构 | `const { code, data } = res; if (code === 0) { ... }` |

### Day06 — Vue 组件：看懂 `<script>` 里的东西

> **为什么学**：模板看懂了，但 `data()`、`methods`、`computed`、`watch`、`props`、`$emit` 这些才是逻辑核心。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| `data()` | 组件的本地状态 | 类的成员变量 | ⭐⭐⭐ |
| `methods` | 组件的方法 | 类的方法 | ⭐⭐⭐ |
| `computed` | 计算属性（有缓存） | getter 方法 + 缓存 | ⭐⭐⭐ |
| `watch` | 监听数据变化 | `PropertyChangeListener` | ⭐⭐ |
| `props` | 父传子的参数 | 构造器参数 | ⭐⭐⭐ |
| `$emit` | 子传父的事件 | 回调函数 | ⭐⭐⭐ |
| 生命周期 | `created` / `mounted` | `@PostConstruct` / `init()` | ⭐⭐⭐ |

```js
// 项目中的组件结构（看懂就是胜利）
export default {
    name: "UserList",                    // 组件名
    mixins: [JeecgListMixin],            // 混入（≈ 继承工具类）
    components: { CommonTable },         // 注册子组件
    props: { userId: String },           // 父组件传过来的参数
    data() {                             // 本地状态（≈ 成员变量）
        return { columns: [], loading: false };
    },
    computed: {                          // 计算属性（有缓存）
        displayName() { return this.user.name || '未知'; }
    },
    watch: {                             // 监听器
        userId(newVal) { this.loadData(); }
    },
    created() { this.loadData(); },       // 生命周期：组件创建后执行
    methods: {                           // 方法
        async loadData() { ... },
        handleEdit(row) { ... }
    }
}
```

**实践**：写一个父组件 + 子组件，父组件传 `title` 给子组件，子组件通过按钮把用户操作 `$emit` 回父组件。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| data/methods | `data() { return { queryParam: {...} } }` |
| computed | `computed: { hasSelected() { return this.selection.length > 0 } }` |
| props | `props: { visible: Boolean, editData: Object }` |
| $emit | `this.$emit('update:visible', false)` |
| created/mounted | `created() { this.loadData(); }` |

### Day08 — Element UI：UI 组件库速查

> **为什么学**：项目用 Element UI 2.5，`el-table`、`el-form`、`el-dialog` 到处都是。你不用全记住，但要能**认出来**。

**核心组件速查表**：

| 组件 | 标签 | 在项目中干什么 | 优先级 |
|------|------|---------------|--------|

### Day11 — CommonTable：啃透项目核心组件

> **为什么学**：你们项目强制要求所有表格用 `CommonTable`，这是全项目出现频率最高的组件。啃透它，大半页面你都能看懂。

```vue
<!-- 项目页面中反复出现的模式 -->
<template>
    <common-table
        ref="refTable"
        :dataSource="dataSource"
        :columns="columns"
        :pagination="ipagination"
        :loading="loading"
        @handleCurrentChange="handleTableChange"
        @handleSizeChange="handleSizeChange"
    >
        <el-table-column slot="table_oper" label="操作" fixed="right">
            <template slot-scope="scope">
                <el-link type="primary" @click="handleEdit(scope.row)">编辑</el-link>
            </template>
        </el-table-column>
    </common-table>
</template>
```

**逐行解释**：

| 代码 | 含义 |
|------|------|
| `:dataSource="dataSource"` | 把 JS 中的 `dataSource` 数组传给表格 |
| `:columns="columns"` | 列定义数组 `[{prop:'name', label:'姓名'}]` |
| `:pagination="ipagination"` | 分页信息 `{current:1, total:0, pageSize:10}` |
| `:loading="loading"` | 加载中状态 |
| `@handleCurrentChange="..."` | 翻页时触发的方法 |
| `slot="table_oper"` | 在表格中插入自定义"操作列" |
| `slot-scope="scope"` | `scope.row` 拿到当前行的数据 |

**实践**：找到 CommonTable 源码（`src/components/views/table/CommonTable.vue`），对照你的 Java 项目中的 BaseController/BaseService，理解"公共组件提效"的思路。

### Day12 — JeecgListMixin + CRUD 流程：看懂增删改查

> **为什么学**：项目中的列表页都混入了 `JeecgListMixin`，它提供了 `loadData()`、`searchQuery()`、`searchReset()` 等方法，不懂它就不知道为什么这些方法突然能用了。

| 知识点 | 学会什么 | Java 类比 | 优先级 |
|--------|----------|-----------|--------|
| Mixin | 混入，多组件共享逻辑 | 抽象父类 / 接口默认方法 | ⭐⭐⭐ |
| `JeecgListMixin` | 提供了列表页的标准流程 | `BaseController` | ⭐⭐⭐ |
| CRUD 流程 | 查 → 增 → 改 → 删 | Controller → Service → DAO | ⭐⭐⭐ |

```js
// 一个标准 CRUD 操作的数据流
// 查询
searchQuery() → loadData() → getAction(url.list, queryParam) → res.data.records → dataSource

// 新增
handleAdd() → dialogVisible = true → 填表单 → handleSave()
    → httpAction(url.add, formData, 'post') → this.$message.success('新增成功') → loadData()

// 编辑
handleEdit(row) → editData = {...row} → dialogVisible = true → 修改表单
    → handleSave() → httpAction(url.edit, formData, 'put') → loadData()

// 删除
handleDelete(row) → this.$confirm('确认删除？') → httpAction(url.delete, {id: row.id}, 'delete') → loadData()
```

**实践**：打开项目中一个列表页 `.vue` 文件，按上述流程在代码中标注每一步对应的位置。

| 要能看懂 | 项目中的代码长这样 |
|----------|-------------------|
| Mixin 引入 | `mixins: [JeecgListMixin]` |
| 查询 | `searchQuery() { this.queryParam.pageNo = 1; this.loadData(); }` |
| 新增 | `httpAction(this.url.add, formData, 'post').then(res => { if (res.code == 0) { ... } })` |
| 删除确认 | `this.$confirm('确认删除？', '提示', { type: 'warning' }).then(() => { ... })` |

### Day14 — Bug 调试实战：前端问题排查套路

> **为什么学**：你的目标是"能改前端 bug"。学完前面的知识后，Day14 专门练怎么排查问题。

**常见 Bug 类型及排查思路**：

| 症状 | 最可能的原因 | 排查工具 |
|------|-------------|----------|
| 点了没反应 | 事件没绑定 / 方法未定义 | F12 → Console 看报错 |
| 数据不显示 | 接口没返回 / 数据没赋值到 dataSource | F12 → Network 看接口 |
| 样式错乱 | CSS 被覆盖 / scoped 没加 | F12 → Elements 看样式 |
| `undefined` / `null` | 对象解构层级不对 | `console.log` / debugger |
| 路由跳不过去 | path 写错 / 权限 meta 限制 | F12 → Console |
| 接口 401/403 | Token 过期 / 权限不足 | F12 → Network → Headers |

**前端调试三板斧**：

```
1. F12 → Console   看报错信息（等于看 Java 的异常堆栈）
2. F12 → Network   看接口请求/响应（等于看 HTTP 请求日志）
3. F12 → Sources   打断点调试（等于 IDEA 的 Debug 模式）
```

**实践**：在 Day01 的 `hello.html` 中故意制造一个 bug（比如把 id 写错），练习用 F12 定位修复。
